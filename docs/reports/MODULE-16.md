**What works now:**
- **The appliance does not run without a license.** Every package carries a license token signed by the Control Plane (Ed25519) and bound to that deployment and that installation; the appliance verifies it against the public key **pinned into the edge image at build time**, checks the binding and the dates, and runs PSA connection tests and ticket synchronization only while the verdict is *valid* or *grace*. A copied image, a copied package, a token for another appliance, a forged or altered token, a suspended, revoked or lapsed license: all stop PSA work, with the reason on the appliance's status page and in the dashboard.
- **Outage tolerance is kept.** Tokens are valid for 30 days and renewed on every heartbeat; after expiry a 14-day grace period keeps the client working while the Control Plane is unreachable, and the status page says until when. An explicit *inactive* answer from the Control Plane (license suspended, expired or revoked; deployment suspended or decommissioned) revokes at once.
- **Keys you control.** The signing seed is the `LICENSE_SIGNING_KEY` secret (generated by every setup script); the public key, its id and the base64 form for image builds are published at `GET /settings/licensing-key`; `pnpm edge:build` and `scripts/vps/cp.sh build` pin it into the image automatically. Images built without a key fall back to the copy in the package and report that honestly (*key source: package*).
- **Everyone can see the verdict.** The appliance reports its own verification in the security report; the deployment overview shows *Appliance license token* (state, renewal deadline, key id and source, *PSA work stopped* when blocked), the health page shows the row and the findings `appliance_license_<state>`, and the local admin shows the state pill, a red banner when blocked, an informational banner during grace, and disables *Sync now*.
- **Nothing to reinstall.** Packages generated before this module have no token file; an upgraded appliance obtains its token from the first heartbeat against the upgraded Control Plane.
- **Verified on a real appliance** (Docker suite): the agent verifies the package token with the key pinned in the image; suspending the license on the Control Plane stops PSA work within a heartbeat (banner, *Sync now* disabled, a requested synchronization does not run, heartbeats continue, health shows the finding); resuming renews the token and the pending synchronization runs; a tampered stored token is refused immediately and healed by the next renewal.

**Honest limits:**

| Area | Status |
|---|---|
| Key rotation | Supported but manual and coupled to an image roll-out (runbook §11): appliances verify with the key pinned in the image they run. |
| Clock trust | Expiry and grace use the appliance's clock; a host with a wrong clock can shorten or lengthen the grace. The Control Plane's `inactive` answer is independent of clocks. |
| Feature or seat entitlements | Not modelled; the token carries the plan name only. |
| Appliance-side tamper proofing | The stored token can be altered on the host (then refused); the pinned key and the binary cannot be altered without rebuilding the image, which is the operator's trust boundary anyway. |

## Security

- **Signature and binding.** Ed25519 over the exact base64url claim segment; claims name the key id, deployment, installation, license and dates. The verifier refuses a wrong key id even when the signature would verify, a token for another deployment or installation, an unreadable or altered token, and anything after expiry plus grace or after the license term. Unit-tested on both sides (contracts in TypeScript, `internal/license` in Go), including a 64-byte signature length check and base64url-only input.
- **Trust anchor.** The public key is compiled into the image; the package copy is only a fallback for images built without one, and the appliance reports which was used so an operator can tell a properly built image from a development one. The signing seed never leaves the Control Plane: not in packages, images, logs or reports (asserted: the agent status carries no token).
- **No new remote power.** Licensing answers ride on the existing mTLS heartbeat; the only effect of an `inactive` answer is that PSA work pauses — tickets, data and the local admin stay, exactly as with suspension. There is still no remote wipe or uninstall.
- **Secret handling.** `LICENSE_SIGNING_KEY` is validated at boot like the other secrets (exactly 32 bytes), generated by every setup path, documented in the secret inventory, and absent from the evidence (secret scan 0 hits).
