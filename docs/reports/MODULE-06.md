## Edge image (`apps/edge`)

| Part | Implementation |
|---|---|
| Build | Multi-stage `Dockerfile`: `golang:1.25-alpine` runs `go vet` and `go test`, then builds a static binary (`CGO_ENABLED=0`, `-trimpath`, version via `-ldflags`). The runtime is `gcr.io/distroless/static-debian12:nonroot`, with `USER 10001:10001` and the entrypoints as symlinks. |
| Dependencies | `github.com/jackc/pgx/v5` v5.11.0, plus its standard transitive modules (`go.sum` verified) |
| `edge-migrate up` | Idempotent initialization, in order: <ol><li>Wait for PostgreSQL.</li><li>Create or sync `psa_edge_app` and `psa_edge_inspector` (NOSUPERUSER, NOBYPASSRLS; passwords from host secrets; `format('%I','%L')` for DDL).</li><li>Revoke PUBLIC access.</li><li>Take an advisory lock.</li><li>Apply checksummed embedded migrations; a changed migration is refused.</li><li>Run the **identity guard**: refuse a database that belongs to another deployment.</li><li>Record identity, PSA connection and services from `config/edge.json`.</li><li>Verify all required tables and primary keys, that the inspector can read **no** table, and that both roles can log in.</li><li>Audit the run.</li></ol> |
| `edge-api` | Local application API and **administration / setup UI**, published on `127.0.0.1` only (table below) |
| `edge-worker` | Every 30 s: keeps `psa_connections.status` at `not_configured` or `credentials_present`. It never sets `verified`, which a CHECK constraint also blocks without a test time. It also records its liveness. No PSA call. |
| `edge-agent` | Collects the database report as the **catalog-only inspector**: availability, version, size, schema version via a SECURITY DEFINER function, and the table inventory. <ul><li>Buffers reports in a bounded outbox (50 files) on the `edge-logs` volume.</li><li>`edge-agent status [--require-enrolled]` reports `not_enrolled` and the token expiry truthfully.</li></ul> |
| Tooling | `pnpm edge:test` and `pnpm edge:build` run Go and the build through Docker; Go is not installed locally. The build copies its context to the WSL file system, because building from `/mnt/<drive>` stalls. |

**Local admin / setup UI (`edge-api`):**

| Feature | Detail |
|---|---|
| First-run setup | Creates the single local administrator inside an exclusive lock. Password policy: at least 12 characters, not containing the user name. Hashed with PBKDF2-SHA256 at 600,000 iterations. |
| Sign-in | Generic error message; locks for 15 minutes after 5 failures; the same work factor for unknown users |
| Sessions | Opaque token, stored as SHA-256; cookie `HttpOnly` + `SameSite=Strict`; 8 h; per-session CSRF token on every form |
| Request guards | <ul><li>**Host must be loopback**: other names get 421 (DNS rebinding).</li><li>Cross-origin `POST` → 403.</li><li>CSP `default-src 'none'`, frame-deny, `no-store`, 64 KB body limit.</li></ul> |
| PSA credentials | Fields from the package's descriptor, with password inputs for secrets. Stored with **AES-256-GCM using the host data key**, bound to the connection and field. Never displayed again. Audited by field key only. |
| Status page | Identity, database, schema, the 13-table inventory, PSA credential status ("connection test: not run"), services, last backup, enrollment ("not enrolled") and the redacted integration log |
| `GET /healthz` | 200 `ok` / 503 `degraded` from a real database ping; used by the Docker healthcheck |

## Client database (`0001_initial.sql`)

**13 tables:**

| Table | Purpose |
|---|---|
| `app_metadata` | Deployment, installation and client identity, schema version, timestamps |
| `psa_connections` | Provider, endpoint, non-secret configuration and status, with a "verified needs a test" CHECK |
| `credential_store` | Ciphertext, a 12-byte nonce and key version; unique per field |
| `service_configurations` | Services; a PSA link is required for services that use a PSA |
| `helpdesk_tickets` | External key unique per connection; status and priority split; SLA timestamps |
| `ticket_events` | Idempotency key and payload hash |
| `sync_runs` | Finish-time CHECKs |
| `audit_events` | Append-only |
| `integration_logs` | Redacted, append-only |
| `backup_runs` | A succeeded backup needs a file and SHA-256 |
| `local_admin_users` | Unique lower-case user name; hash format CHECK |
| `local_admin_sessions` | Session token hashes and CSRF tokens |
| `schema_migrations` | Applied migrations and checksums |

- Foreign keys, indexes and `updated_at` triggers are in place.
- **Grants:** the app role has DML; it has INSERT and SELECT only on `audit_events` and `integration_logs`, and SELECT only on `backup_runs` and `schema_migrations`. The **inspector role has no table privilege**; only `edge_schema_status()` is granted to it.
