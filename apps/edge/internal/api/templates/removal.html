Removal

How this appliance ({{.Code}}, Compose project {{.Project}}) is retired. Nothing here is ever triggered remotely: the provider can decommission the deployment, the removal itself is always run by you on this host.

{{if .Decommissioned}}
Decommissioned by the provider since {{.Since}}. The appliance no longer reports to the Control Plane; PSA connection tests and ticket synchronization have stopped. Tickets, data and this administration page stay on this host until you remove the appliance.
{{else}}
The provider has not decommissioned this deployment (agent state {{.AgentState}}). Ask your PSA Control Center administrator to decommission it first; the uninstall script refuses to wipe an active identity.
{{end}}

Order of operations

  1. Control Plane first. The administrator decommissions the deployment in the dashboard: its machine certificate, enrollment token and package are revoked and open commands are cancelled. This appliance notices at its next heartbeat and stops PSA work.
  2. This host second. Run the uninstall script from the package folder, as the user who installed the appliance.

Stop and keep the data

Containers and networks are removed; the database, logs, backups, agent state, ./secrets and .env stay. scripts/install.sh brings the same installation back.

scripts/uninstall.sh
# Windows
powershell -ExecutionPolicy Bypass -File scripts\uninstall.ps1

Remove everything

Irreversible. Deletes the operational database (locally stored tickets, the encrypted PSA credentials), logs, backups, agent state, ./secrets and .env. Make and check a backup first if the data may still be needed. The deployment ID must be typed to confirm.

scripts/uninstall.sh --wipe --confirm {{.Code}}
# Windows
powershell -ExecutionPolicy Bypass -File scripts\uninstall.ps1 -Wipe -Confirm {{.Code}}

Afterwards delete the package folder; the PSA Edge image can be removed with docker image rm once no other deployment on this host uses it.

Ending the service yourself

The client can end the service from this appliance without the provider: Delete all data and deregister tells the Control Plane over this appliance's own identity to delete every record it holds about this deployment (only an audit event remains there), then deletes the database, logs, credentials and the machine identity here. The Docker resources are removed afterwards with the wipe command above, which then needs no --force.

What the Control Plane keeps

Only metadata: the deployment record, its identity history and the audit trail. Reports, heartbeats, the table inventory and the command history are purged after the provider's retention period. No ticket, credential or database row ever left this host.
